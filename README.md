# ChekMsg v0.4

เครื่องมือคัดกรองข้อความหลอกลวงทางการเงิน ทำงานด้วยกฎที่เขียนไว้ (rules-based) ประมวลผลในเครื่องผู้ใช้ทั้งหมด

> **สิ่งที่เครื่องมือนี้ไม่ได้เป็น:** ไม่ใช่โมเดล AI ไม่มีการเรียนรู้ ไม่มี backend ไม่มีการเก็บข้อมูล
> การ "สอน" ระบบ = แก้ `patterns.json` แล้ว deploy ใหม่ ไม่มีอย่างอื่น

---

## อยากลองเร็ว ๆ ไม่ต้องตั้งอะไร

เปิด `dist/chekmsg-standalone.html` ด้วยการ double-click ได้เลย — เป็นไฟล์เดียวที่รวม engine กับ pattern ไว้ในตัว ใช้ออฟไลน์ได้ ส่งต่อให้คนอื่นทดสอบทาง LINE หรืออีเมลได้

สร้างใหม่หลังแก้ `patterns.json` ด้วย

```bash
npm run build
```

> ตัวที่ deploy จริงบน server ให้ใช้ `index.html` + `patterns.json` แยกไฟล์ เพราะแก้ wording แล้วไม่ต้อง build ใหม่
> ไฟล์ standalone มีไว้สำหรับทดสอบและส่งต่อเท่านั้น

## รันในเครื่อง

ต้องเปิดผ่าน web server เพราะหน้าเว็บโหลด `patterns.json` ผ่าน `fetch` (เปิดด้วยการ double-click ไฟล์จะไม่ทำงาน เพราะติด CORS ของ `file://`)

```bash
cd chekMsg-v0.4
python3 -m http.server 8080      # หรือ npx serve
# เปิด http://localhost:8080
```

## Deploy ขึ้น server

เป็น static site ล้วน คัดลอกทั้งโฟลเดอร์ไปวางได้เลย

```bash
# nginx / apache
rsync -av ./ user@server:/var/www/chekmsg/

# หรือ Cloudflare Pages / Netlify / S3 + CloudFront
# ไม่ต้อง build ไม่ต้องตั้งค่า runtime ไม่มี environment variable
```

สิ่งเดียวที่ต้องตั้งค่าใน nginx คือให้ `.json` ถูก serve ด้วย `application/json` (ค่า default ถูกอยู่แล้ว)

## เพิ่ม / แก้ wording — วิธีที่ง่ายที่สุด

เปิด `admin.html` (ต้องผ่าน web server) จะได้หน้าจัดการที่ทำ 4 อย่างในที่เดียว

```bash
python3 -m http.server 8080
# เปิด http://localhost:8080/admin.html
```

| ส่วน | ทำอะไรได้ |
|---|---|
| ทดสอบข้อความ | วางข้อความจริง ดูผลพร้อมสัญญาณที่จับได้และคะแนนแต่ละตัว |
| ผลชุดทดสอบ | รันใหม่อัตโนมัติทุกครั้งที่แก้ เทียบกับตอนเปิดหน้า |
| คลัง pattern | ค้นหา กรอง แก้คำ แก้น้ำหนัก เปลี่ยนหมวด ลบ เพิ่มใหม่ |
| ดาวน์โหลด | `patterns.json` ตัวใหม่ (เลข version ขยับให้เอง) และรายงานผลทดสอบ `.md` |

**หัวใจของหน้านี้คือช่องเทียบผลก่อน-หลัง** เพิ่มคำแล้วมันจะบอกทันทีว่าเคสไหนดีขึ้น เคสไหนพังลง เช่นถ้าใส่คำว่า "ชำระ" น้ำหนัก 5 เข้าไป มันจะเตือนว่าข้อความ "ชำระเงินเรียบร้อย ค่าน้ำประปา 285 บาท" ที่เคยตอบถูกกลับตอบผิดแล้ว — นี่คือกลไกที่กันไม่ให้ยิ่งเพิ่มคำยิ่งแย่ลง

ขั้นตอนใช้งานจริง

1. เปิด `admin.html` → เพิ่ม/แก้คำ → ดูช่องเทียบผล
2. ถ้าไม่มีอะไรพังลง กด **ดาวน์โหลด patterns.json**
3. เอาไฟล์ที่ได้ไปวางทับตัวเดิมบน server
4. กด **ดาวน์โหลดรายงาน .md** เก็บไว้เป็นหลักฐานว่าเวอร์ชันนี้วัดได้เท่าไร

หน้านี้ไม่บันทึกอะไรลง server — แก้ในหน่วยความจำเบราว์เซอร์ล้วน ปิดแท็บโดยไม่ดาวน์โหลด = การแก้หายหมด

## เพิ่ม / แก้ wording — แก้ไฟล์ตรง ๆ

แก้ `patterns.json` ไฟล์เดียว ไม่ต้องแตะโค้ด

```json
{ "id": "s_th_new_scam", "lang": "th", "cat": "delivery", "match": "ค่าภาษีนำเข้า", "w": 4 }
```

| ฟิลด์ | ความหมาย |
|---|---|
| `id` | ต้องไม่ซ้ำ ใช้อ้างอิงตอนดู log การทดสอบ |
| `lang` | `th` หรือ `en` — มีผลกับความยาวหน้าต่างตรวจคำปฏิเสธ |
| `cat` | หมวด ต้องมีอยู่ใน `categories` — **หมวดเดียวกันนับสูงสุดครั้งเดียว** |
| `match` | ข้อความที่จะค้นหา (ไม่สนตัวพิมพ์เล็กใหญ่ และทนต่อการแทรกช่องว่าง) |
| `w` | น้ำหนัก 1–5 |

**ตั้งน้ำหนักอย่างไร**

| w | ใช้เมื่อ | ตัวอย่าง |
|---|---|---|
| 1 | คำที่พบในข้อความปกติได้บ่อย | `urgent`, `ด่วน` |
| 2–3 | บ่งชี้ได้แต่ไม่เด็ดขาด | `กดลิงก์`, `พาร์ทไทม์` |
| 4–5 | แทบไม่พบในข้อความจริง | `ไม่เช็คบูโร`, `send your otp` |

**หลังแก้ทุกครั้ง ต้องรัน test**

```bash
npm test
```

ถ้าตัวเลข `hard miss` เพิ่มขึ้น แปลว่าคำที่เพิ่งใส่ทำของเดิมพัง ให้ลดน้ำหนักหรือเขียนให้เฉพาะเจาะจงขึ้น

## ชุดทดสอบ

```bash
npm test                                  # พิมพ์ผลออกหน้าจอ
npm run test:report                       # เขียน tests/last-report.md
node tests/run-tests.js --set adversarial # รันเฉพาะชุดเดียว
```

มี 6 ชุด แต่ละชุดตอบคำถามคนละข้อ

| ชุด | ใช้ตอบคำถามว่า | อ้างเป็น accuracy ได้ไหม |
|---|---|---|
| `regression_v03` | แก้แล้วของเดิมพังไหม | **ไม่ได้** — เขียนจาก keyword ของ v0.3 เอง |
| `holdout_bank_real` | ข้อความธนาคารจริงถูกตีว่าสแกมไหม | ได้ |
| `holdout_scam_th` | จับสแกมไทยที่ระบาดจริงได้ไหม | ได้ |
| `holdout_scam_en` | จับสแกมภาษาอังกฤษได้ไหม | ได้ |
| `holdout_ambiguous` | เครื่องมือมั่วเดาหรือเปล่า | ได้ |
| `adversarial` | ระบบเปราะแค่ไหนเมื่อคนร้ายเลี่ยงคำ | **ตัวเลขที่สำคัญที่สุด** |

**อย่าไล่แก้ pattern ให้ผ่านชุด `adversarial` ทีละข้อ** — จะกลายเป็นการจำข้อสอบ ซึ่งคือปัญหาเดิมของ v0.3 ที่ทำให้ตัวเลข 15/15 ไม่มีความหมาย ให้ใช้ชุดนี้ดูแนวโน้มแทน ถ้าเขียนข้อความกัดใหม่แล้วยังหลุดเยอะ แปลว่าถึงเพดานของวิธี rules-based แล้ว

การให้คะแนนแยก 3 ระดับเพราะความผิดพลาดไม่เท่ากัน

- **correct** — ตอบตรง
- **soft miss** — ตอบ `unsure` ทั้งที่ควรตอบชัด ปลอดภัยแต่ไม่ช่วยอะไร
- **hard miss** — ตอบผิดข้าง โดยเฉพาะสแกมที่ถูกตอบว่า legit คือความผิดพลาดที่ทำให้คนเสียเงินจริง test runner จะ exit code 1 เมื่อเจอกรณีนี้ เอาไปต่อ CI ได้

## โครงสร้าง

```
chekMsg-v0.4/
├── index.html          หน้าเว็บสำหรับผู้ใช้ทั่วไป — UI + i18n
├── admin.html          หน้าจัดการ pattern สำหรับคนดูแล
├── engine.js           detection logic ใช้ได้ทั้งเบราว์เซอร์และ Node
├── test-core.js        สูตรให้คะแนนและสรุปผล ใช้ร่วมกันทั้ง admin และ CLI
├── patterns.json       pattern library ← แก้ไฟล์นี้เพื่อเพิ่ม wording
├── build.js            รวมทุกอย่างเป็นไฟล์เดียว
├── package.json
├── dist/
│   └── chekmsg-standalone.html   ไฟล์เดียว double-click เปิดได้
└── tests/
    ├── testset.json    ชุดทดสอบ 6 ชุด
    └── run-tests.js    test runner (CLI)
```

`test-core.js` มีอยู่เพื่อไม่ให้สูตรคำนวณ accuracy อยู่สองที่แล้วค่อย ๆ เพี้ยนออกจากกัน — ตัวเลขที่ `admin.html` แสดงกับที่ `npm test` พิมพ์ออกมาจึงมาจากโค้ดชุดเดียวกันเสมอ

`engine.js` คืนค่าเป็น **รหัสหมวด** ไม่ใช่ข้อความ ชั้น UI เป็นคนแปลเป็นภาษาที่ผู้ใช้เลือก ถ้าจะเพิ่มภาษาที่สาม แก้ `T` ใน `index.html` กับ `categories` ใน `patterns.json` เท่านั้น ไม่ต้องแตะ logic

## OCR — อ่านข้อความจาก screenshot

สแกมส่วนใหญ่มาถึงผู้ใช้เป็นภาพ ไม่ใช่ข้อความ หน้าเว็บจึงรับภาพได้ 3 ทาง: ลากมาวาง, กด `Ctrl+V` วางภาพที่ copy ไว้, หรือเลือกไฟล์

มีให้เลือก 2 โหมด สลับด้วยตัวแปรเดียว

| โหมด | ตั้งค่ายังไง | ภาษาไทย | ภาพออกจากเครื่อง | ต้องมีอะไร |
|---|---|---|---|---|
| **Typhoon OCR** | ใส่ URL ใน `OCR.proxyUrl` | แม่น — โมเดลทำมาเพื่อไทยโดยเฉพาะ | ออก | ตัวกลางใน `ocr-proxy/` |
| **Tesseract** | ปล่อย `proxyUrl` ว่าง | เพี้ยนมาก ใช้งานจริงแทบไม่ได้ | ไม่ออก | ไม่ต้องมีอะไร |

```js
const OCR = {
  proxyUrl: '',        // ใส่ URL ของ ocr-proxy แล้วจะสลับไปใช้ Typhoon อัตโนมัติ
  cdn: 'https://cdn.jsdelivr.net/npm/tesseract.js@5/dist/tesseract.min.js',
  langs: 'tha+eng',
  maxDim: 1800,        // ย่อด้านยาวสุดก่อนส่ง
  timeoutMs: 60000
};
```

**ทำไมต้องมีตัวกลาง** — API key ใส่ในหน้าเว็บไม่ได้ ใครก็เปิด view-source เอาไปใช้ได้ ตัวกลางจึงเก็บ key ไว้ฝั่ง server วิธีติดตั้งอยู่ใน [`ocr-proxy/README.md`](ocr-proxy/README.md) เลือก deploy บน Cloudflare Workers, Docker หรือรันตรง ๆ ก็ได้ และถ้าไม่อยากให้ภาพออกนอกองค์กรเลย โมเดล Typhoon เป็น open weights รันเองได้ผ่าน vLLM แล้วชี้ `TYPHOON_BASE_URL` มาที่เครื่องตัวเอง

สิ่งที่ต้องรู้ไม่ว่าจะใช้โหมดไหน

- ข้อความที่อ่านได้จะเข้าไปในช่องกรอกให้ผู้ใช้ **ตรวจทานและแก้ก่อน** กดตรวจสอบเสมอ ไม่ตรวจอัตโนมัติทันที
- ภาพถูกย่อเหลือด้านยาว 1,800 px ในเบราว์เซอร์ก่อนส่ง ลดขนาดและตรงกับที่โมเดลถูกฝึกมา
- โหมด Typhoon จะแสดงข้อความแจ้งผู้ใช้ว่าภาพถูกส่งออกไปประมวลผล — **อย่าลบข้อความนี้** เพราะภาพ SMS ธนาคารเป็นข้อมูลส่วนบุคคล
- โหมด Tesseract โหลดไลบรารีจาก CDN เฉพาะตอนเลือกภาพครั้งแรก คนที่พิมพ์เองไม่ต้องโหลดอะไรเพิ่ม

## ที่ยังไม่ได้ทำ

- **ปุ่มรายงานผลผิด** — โค้ดพร้อมแล้ว ใส่ URL ที่ตัวแปร `REPORT_FORM_URL` ใน `index.html` แล้วปุ่มจะขึ้นเอง (ตั้งใจให้เป็นฟอร์มภายนอกเพื่อไม่ต้องมี backend และไม่เสียจุดแข็งด้าน privacy)
- **ตรวจ URL แบบ real-time** — ต้องเรียก API ภายนอก ซึ่งแปลว่าต้องส่งข้อมูลออกจากเครื่อง ขัดกับหลักการปัจจุบัน ถ้าจะทำต้องขอความยินยอมจากผู้ใช้ก่อน
- **ชั้น LLM** — ถ้าจะเพิ่ม ควรเรียกเฉพาะเมื่อผลออกมา `unsure` เท่านั้น และต้องมี backend เพื่อไม่ให้ API key รั่ว

## ข้อจำกัดที่ต้องบอกผู้ใช้ตามตรง

ระบบนี้จับได้เฉพาะสิ่งที่มีคนใส่ไว้ใน `patterns.json` แล้วเท่านั้น สแกมที่ใช้คำใหม่จะได้ผลว่า "ยืนยันไม่ได้" ไม่ใช่ "เป็นสแกม" ดังนั้น

- **"น่าจะเป็นข้อความปกติ" หมายถึง "ไม่พบสัญญาณอันตราย" ไม่ใช่ "ปลอดภัย"**
- ผลลัพธ์เป็นตัวช่วยตัดสินใจ ไม่ใช่คำตัดสิน
- ข้อความนี้เขียนไว้ในหน้าเว็บแล้วในส่วน "เครื่องมือนี้ตัดสินอย่างไร" — อย่าลบออกตอนแก้ดีไซน์
